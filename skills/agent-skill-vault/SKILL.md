# 스킬 보관·복원 도우미

필요한 스킬은 남기고 선택한 스킬은 에이전트가 찾지 않는 위치에 보관한다. 자동 영구 삭제를 제공하지 않는다.

## 남길 항목 판단

설치 위치가 확정되어 있으면 그 위치만 조사한다. 여러 에이전트가 있다면 루트별로 별도 작업한다. 제품이 관리하는 플러그인은 파일 이동 전에 제품의 관리 방식을 확인한다.

사용자가 계속 사용할 기능, 프로젝트가 참조하는 기능, 설치·복원에 필요한 관리 도구는 남긴다. 이름이 비슷하다는 이유로 같은 기능이라고 판정하지 않는다. 폴더 수정 시각은 실행 횟수의 근거가 아니다.

사용 정보가 제공되면 출처와 관측 기간을 함께 살펴본다. 기록이 없는 항목에는 사용 여부를 알 수 없다고 적는다. 사용 횟수가 적더라도 계절성 작업이나 가끔 필요한 기능일 수 있으므로 횟수만으로 이동하지 않는다. 전체 대화 로그를 읽어야 한다고 전제하지 않는다.

## 목록에서 보관까지

Python 3.10 이상 helper와 [보관함 작업 안내](references/vault-operations.md)를 사용한다. helper 경로는 현재 스킬 폴더에서 절대 경로로 구한다.

1. `catalog`로 실제 파일 묶음의 해시와 경로를 확인한다. 시스템 영역·링크·저장소 등 자동 취급이 어려운 항목은 보존 대상으로 나타난다.
2. 선택한 항목을 다른 스킬, 프로젝트 지침, 도구 설정에서 참조하는지 조사한다. 이 조사 범위와 의존 관계를 조사표로 기록한다. 목록이 바뀌면 조사표를 갱신한다.
3. 대상이 이미 구체적으로 선택되어 있으면 그 범위에서 `park`를 실행한다. 추천만 요청받았거나 선택이 모호하면 후보와 보존 이유를 먼저 제시한다.

helper는 설치 루트 하나와 보관함 하나를 받는다. 여러 항목은 하나씩 옮기며 중간 실패 시 이미 성공한 항목을 보고하고 남은 작업을 중단한다. 임의의 설치 루트를 계속 추가하거나 폴더를 통째로 정리하지 않는다.

## 인수증과 복원

보관함은 조사한 모든 에이전트의 스킬 검색 경로 밖에 둔다. 다른 프로세스가 스킬 폴더를 변경하는 동안 이동하지 않는다. 보관함과 설치 루트는 폴더를 이동할 수 있는 같은 파일시스템이어야 한다.

각 이동은 별도 티켓을 만들고 인수증을 먼저 남긴다. 인수증의 경로를 사용자에게 알려준다. 이동이 중단되면 `status`로 원래 위치와 보관 위치를 함께 확인한다. 인수증이 있다고 이동 완료로 표현하지 않는다.

복원 요청에는 `restore`를 사용한다. 같은 이름의 다른 폴더가 원래 위치에 생겼거나 보관 중 내용이 바뀌면 자동 복원을 중단한다. 내용 확인 없이 덮어쓰거나 영구 삭제하지 않는다.

보고에는 실제 보관 또는 복원된 이름·원래 경로·티켓을 적는다. 보호된 항목과 미처리 항목도 이유와 함께 남긴다. 모델 성능 향상이나 비용 감소는 별도로 확인한 경우에만 설명한다.
